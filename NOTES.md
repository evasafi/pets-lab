# PETs Lab: research notes

## Setup
- Python 3.12, synthetic data (5,000 aid recipients, seed 42), generated by src/generate_data.py
- Shared problem: release per-district medical-need counts and mean income, and train a model predicting medical_need, without exposing individuals

## Finding 1: naive anonymization (src/linkage_attack.py)
- Dropping person_id leaves 50.9% of records unique on (age, sex, district, household_size)
- An attacker with a named side list of 500 people re-identified 51.4% exactly
- Caveat: the "medical status exposed" figure (81.6%) is inflated by the base rate (about 82.5% have no medical need). Replace with a metric on medical_need = True only
- Assumption: attacker knows targets are in the dataset; exact age makes uniqueness higher than coarse age bands would

## Finding 2: Laplace mechanism on district counts (src/dp_counts.py)
- Noise scale = sensitivity / epsilon, independent of group size, so relative error is roughly 1 / (epsilon * count)
- D01 (true count 5): 206% error at eps 0.1, 19% at eps 1. D03 (167): 6% at eps 0.1
- Parallel composition: the 12-district histogram costs eps once, because each person is in exactly one district
- Caveat: aggregate release vs record-level release are different threat models, so not yet comparable to Finding 1

## Finding 3: Additive secret sharing (src/secret_sharing.py)
- Three orgs (D01-D04, D05-D08, D09-D12) computed the global medical-need count (875) without revealing local counts (295, 402, 178). Shares of the same value differ on every run
- Limit: the output itself leaks. If B and C collude, 875 - 402 - 178 = 295 recovers A exactly. Secret sharing protects the computation, not what the result reveals

## Finding 4: Secure sum + distributed Laplace noise (src/secure_dp_sum.py)
- Noise split into differences of Gamma(1/n) pieces, one per org; the pieces sum to one Laplace(1/eps) draw
- Measured mean abs error on the total at eps = 1: 0.98 (theory: 1.0)
- With B and C colluding, mean abs error on A's count is 0.46: they subtract their own pieces, leaving only A's piece. Roughly half the noise protects A. The piece is not Laplace, so the effective epsilon was not computed
- Mitigation (not implemented): size each piece for worst-case collusion, at a cost in accuracy
- DP protects individuals, not org-level totals: A's total is known to about +-1
- Caveats: numpy RNG is not cryptographically secure; fixed-point encoding of float noise; real systems use discrete noise and secure randomness (e.g. OpenDP). Semi-honest model: parties follow the protocol

## Finding 5: FedAvg vs centralized vs local-only, full-size orgs (src/federated.py)
- Test AUC: centralized 0.657, FedAvg 0.657, local-only 0.652 to 0.658. No meaningful difference
- Reason: orgs are large (680 to 1704 training rows) and near-identical in distribution (district does not affect medical_need in the generator); the data signal is weak (ceiling about 0.66). This is a null result: FL does not hurt, but nothing here shows it helps
- Shortcut: feature scaling was computed on pooled training data, which real orgs could not do without sharing statistics

## Finding 6: when does FL help? (src/federated_small.py)
- Mean test AUC over 20 random draws per size, local-only vs FedAvg: 20 rows/org 0.562 vs 0.602; 50 rows 0.585 vs 0.622; 150 rows 0.624 vs 0.647; 500 rows 0.651 vs 0.657
- The gap shrinks as data grows (0.040, 0.037, 0.023, 0.006). At 20 to 50 rows the gap is about one std across draws, so individual runs overlap. No paired significance test was run
- Caveats: orgs are near-IID (favorable to FL); fixed test set; FedAvg effectively draws on 3x the data, which is the point of collaboration. Local-only and FedAvg use the same training code and total step count
- FL alone is not a privacy guarantee: weight updates can leak (gradient inversion, membership inference). Not tested here. Proper protection is secure aggregation plus noise, as in Finding 4

## Finding 7: HE private inference with CKKS (src/he_inference.py)
- Scenario: client encrypts a person's features, server computes the linear score of a trained logistic regression on the ciphertext, client decrypts. The sigmoid is applied client-side after decryption
- 200 predictions: mean error vs plaintext 4.9e-07 (max 6.8e-07); 9.9 ms per prediction (encrypt + compute + decrypt; one-time key generation excluded); ciphertext 324 KB vs 40 bytes of raw features
- AUC identical (0.697 plaintext and encrypted) on this 200-person subset; it differs from 0.657 in Finding 5 only because of the small subset (sampling noise)
- Overhead is mostly fixed per ciphertext (these parameters allow 4096 values per ciphertext; we use 5). Packing many people per ciphertext should amortize it. Not tested
- Protects features and score from the server. Does not protect the model (server holds it in plaintext) and does not hide query count or timing. Parameters are common example values; security level not audited

## Finding 8: fairer attack metric and age generalization (src/linkage_attack_v2.py)
- Metric: share of true positives (medical_need) for whom every matching released record is also positive, i.e. the attacker is certain. Replaces the base-rate-inflated figure in Finding 1
- Age band 1 / 5 / 10: unique records 50.9% / 15.6% / 8.1%; re-identified 51.4% / 15.4% / 8.2%; positives exposed with certainty 54.3% / 21.0% / 14.8% (of 81 positives)
- Min group size stays 1 even with 10-year bands, so these are generalizations, not k-anonymous releases. Utility lost by coarsening age not measured
- Only 81 positives in the attacker sample, so the exposure figures are rough (14.8% is about 12 people). Exposure above the overall re-identification rate is consistent with homogeneity (all-positive groups), but unique records and homogeneous groups were not separated

## Finding 9: gradient leakage in FL updates (src/gradient_leakage.py)
- Setup: the attacker (the FL server) sees one plain first-round update computed from a batch of B people, and scores 400 candidates (members plus non-members) by feature alignment (absolute cosine) with the update
- Batch size 1 / 2 / 5 / 20 / 100: membership AUC 1.000 / 0.882 / 0.698 / 0.580 / 0.526; top-1 hit rate 100% / 11.5% / 6.5% / 9.0% / 26.5% (chance 0.2% / 0.5% / 1.2% / 5.0% / 25.0%)
- Batch of 1: the update is proportional to that person's features, so they are recovered exactly. At batch 100 the attack is close to chance. At batch 2 AUC is high but the top-1 hit rate is only 11.5%: the leak shows someone from a small group is present more than it identifies one person
- Caveats: best case for the attacker (fresh model, plain unprotected updates, one round); only 6 features, larger models probably leak more but this was not tested; 200 trials per batch size. The regime where FL helped most in Finding 6 (small orgs) is also where this attack works best
- Not tested: clipping plus noise, or secure aggregation, as defenses
